# Contributing

1. Pick an issue and read its linked files in the Docs repository.
2. Update the relevant story or contract before changing shared behaviour.
3. Keep credentials and private content out of Git.
4. Add component tests and browser coverage where it matters.
5. Check keyboard, accessibility, mobile, and desktop behaviour.
6. Review the full diff before pushing or opening a PR.

Use short branches and Conventional Commit subjects. Generate API types from Backend OpenAPI instead of copying them by hand.

See the [review workflow](https://github.com/VirtuJudge/Docs/blob/main/Planning/Review-Workflow.md).
